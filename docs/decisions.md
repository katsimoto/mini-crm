# Решения и допущения

Для неоднозначных случаев я выбрал следующие правила.

| Вопрос | Решение |
| --- | --- |
| Кто управляет задачами? | Система обслуживает одну компанию. У аккаунта одна роль, которую назначает администратор. Любой постановщик может управлять всеми объектами и задачами независимо от авторства. |
| Можно ли оставить задачу без ответственного? | При создании обязателен один исполнитель. Принятые задачи по-прежнему видны ему, пока их не удалили или не передали другому сотруднику. |
| Что значит удалить задачу или объект? | Запись помечается удалённой и исчезает из рабочих списков. История сохраняется. Объект можно удалить только после того, как все его задачи, в том числе принятые, перенесены или удалены. |
| Когда разрешены правки и переназначение? | Постановщик может менять название, описание, объект и исполнителя любой неудалённой задачи. При переназначении статус сохраняется. Новый исполнитель получает доступ ко всей истории, прежний его теряет. |
| Что происходит с принятой задачей после правки? | «Принята» завершает процесс. Изменение текста или ответственного не запускает повторную приёмку. Запись о приёмке относится к моменту решения. |
| Какие события хранит история? | Создание задачи и каждую смену статуса. В событии сохраняются имя участника на момент действия и время сервера. Комментарий обязателен при возврате, в остальных переходах он добровольный. |
| Что происходит при одновременных изменениях? | Для смены статуса проверяется, что совпадают статус и номер его изменения. Поэтому решение из старой вкладки не применяется к следующему кругу проверки. Из двух конкурирующих переходов проходит один. Для обычных правок текста действует последнее сохранение. |

## Что не успел и что осталось за рамками

Все пять экранов, операции с объектами и задачами, история и публикация демо выполнены. Из обязательных функций ТЗ незавершённых пунктов нет.

Отдельный архив, восстановление удалённых записей и версии содержания я не включал в объём работы. Поэтому, например, из журнала можно узнать, кто принял задачу, но нельзя восстановить точный текст её описания на дату приёмки. Демо опубликовано на Vercel статической сборкой. Для обновления сайта после изменений в GitHub требуется отдельный деплой.
